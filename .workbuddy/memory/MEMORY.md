## 硬纪律（不可绕过）

- **一 F-xx 一 PR**：开工前读上游真源（子 PRD 验收要点 → `docs/05-test-cases/test-Mx.md` 的 oracle → `docs/03-locks/*` → `AGENTS.md` 红线），交付走**双向登记**（文档卡 + 反向清单 + 目录 README + `AGENTS.md` 状态位 + `ci.yml` 一步）。
- **生产零写 / 真实返回 / 证据四要素 / 失败不否定结论**：四条红线写进每份产物，且**尽量做成可静态扫描或可运行期断言**的，不靠人工保证。

## 架构约定

- **新增写面就单独成文件**（`server/tool-executor/` 的既有惯例）：`mcp-client.js`（传输层，零 SQL 零写）、`task-state.js`（任务态写入面，改行只落在 `task` 且带主键条件）。这样 `index.js` 保持「不含改行 / 删行类 SQL」，**`test-f23.mjs` 那条静态零写断言就永远不用改**——扩写面时不去动既有 oracle，是这个拆法的第一目的。**一个模块可以有多个写面**：`server/agent-orchestrator/` 里 `profile.js` 管 MD-13/MD-14、`behavior-store.js` 管 MD-09/MD-10；编排文件（`role.js` / `behavior.js`）**零写语句零裸 SQL**，落库全经写面文件，**取号也不写 `SELECT MAX`**（用写面读面返回的全量自算「库内最大 +1」）。模块级硬红线里那句「本目录只写 X 表」是**清单**、不是「只有一张表」，新增写面时必须同改该句。
- **引入同目录内新 import 会改变「文件间引用图」**：本目录 README 的「文件间引用（本目录内）」段逐文件写明了「谁被别人 import」。把 `behavior.js` 指向 `verification.js`（F-20 复用 F-15 的查询与倒挂口径）后，`verification.js` 就不再是「只由 `../api/index.js` 消费」——**该段与模块级硬红线必须同改**，否则文档与现实不符（这是交付物自检里最容易漏的一项）。
- **「派生优于复制」**：上游已有真源常量时，下游**用 `map` 派生**而不是再抄一份（如五查键序 `RESEARCH_CHECK_SEQUENCE.map(s => s.check_key)`），并在用例里断言 `派生结果.join(">") === 上游常量.join(">")`。改一处不可能漏另一处，且「不复制第二个口径」这条纪律变成可静态核对的断言。
- **值域一律从库读、不内联**：`dict_item`（`dictCodes(db, 'TASK_STATUS')` 等）是唯一真源；代码里不复制中文枚举。
- **叙述文本本体归 `agent-runtime/`，服务端只持「编号 + 判据键 + 来源回指」**：角色指令（`agent.md`）与公共业务指令（`business-rules.md`）的**文本本体只存 `agent-runtime/` 一份**；服务端（`server/agent-orchestrator/role.js`）不内联叙述，只持段落键 / 指令编号 / 判据键，并用例**逐条对齐断言**（读本体 md 抽标题列表 vs 代码常量列表，逐条相等）。配套纪律：常量里的标题须与本体标题**逐字一致**（修饰语放正文），否则「回指不重述」就退化成第二个口径。
- **约定优于重写 oracle**：既有用例的断言能不动就不动；确需扩写面时优先改架构（拆文件 / 缩窄写面），其次才是改用例。
- **前端（`frontend/`，零构建）的前后端分离落点**：全站**唯一网络出口是 `frontend/assets/api.js`**（静态断言「只有它出现 `fetch`」），并带**运行期守卫**（路径必须 `/api/` 开头、不得含 `://`，违反直接抛错不发请求；`BASE` 恒空串）。纪律做成闸，不靠注释。四条配套：① 业务数据只在服务端，前端 `localStorage` 只存会话态（`applied`/`navUnread`），并有用例实测存储键；② 六要素键与序号一律取服务端 `GOAL_FIELDS`，不复制第二个口径；③ **看页面不写库**——进入页面 GET-only，写动作只由显式按钮或「保存后自动跑一次」触发；④ 前端**不自造端点**，接口面缺什么就登记在 `frontend/README.md` §4，不越界补。**F-28 补三条**：⑤ **口径副本必须逐条对齐上游常量**——`U.OPP_FIELDS` 的键序与中文标签被用例逐字比对 `OPPORTUNITY_SIX_ELEMENTS` / `OPPORTUNITY_SIX_ELEMENT_LABELS`（与 `U.SIX_FIELDS` ← `GOAL_FIELDS` 同法）；⑥ **「可回查」类能力必须走上游回查路由**——证据链点开调 `GET /api/evidence-trace/{id}`，前端**不自己拼**「证据 + 查询记录」；⑦ **写请求白名单**——用例断言写请求**只**落在本功能点该用的那条路由，且不出现 `/api/query|query-records|query-recovery|tool-permission|agent-delegations`（把硬红线「前端不发起任何生产写接口调用」做成运行期判据，而非只写注释）。
- **「门禁态」与「空态」刻意分开**（F-28 范式，后续页面沿用）：「这一步的前置动作还没做」（如目标从未跑过机会发现）＝**门禁**，整块收起并指回去执行；「进来了但本轮没有产出」＝**空态**，且要**点明上游口径**（如 M3-F-16「没有足够依据也是合法产出」，不外推为「没有机会」）。两者用不同夹具各自走通，不能共用一个「无数据」分支。
- **「应用层判缺」用「库级放行」做反例（双断言范式）**：当某约束在库级拦不住时（`NOT NULL` 拦不住纯空白串、数值列 `CHECK (x>=1)` 放行 `''`），用例要**先证库级放行**（把那行真的插进去）**再证应用层判缺**（页面/接口给出「不齐」并说明缺哪一项），并把「不会被误标为合格」也断上（如「不齐者不会被标为可回查」）。这样「缺一不可」这类红线是**可复核的双向证据**，不是一句散文。
- **受门禁的语义判断一律做成「可注入判据 + 确定性 fallback」**（F-19 范式，后续 F-20/F-21 同类沿用）：需要 LLM（A-1 ⬜ 未提供）的那一步（如「问题是否适合 HVA 研究」）**不做关键词猜测**——函数接收可选的判定入参（如 `suitability={suitable,reason,signals}`），传了就采纳（`source='provided'`），没传就走**确定性 fallback** 并显式标注 `llm_gated=true`，**既不硬造结论也不硬做**；入参形态非法一律报错、不静默忽略。这样门禁关闭前后**同一套代码**可用，且 oracle 的「三分支」在门禁期内即可被用例真实走通（该 oracle 项登记为「门禁未关闭、非发布门禁」）。
- **「缺信息」不等于「路径未定」**：把「能定则定、缺则如实登记」当作默认口径——如 F-19 的比较条件三项缺了就列入 `missing`（不编造、不静默回退），**但不阻断本步的停止条件**（停止条件只认「路径确定」），补齐动作交给下游功能点。别把上游的缺口变成自己的失败。
- **同一张表的「建行」与「内容填充」可分属两个功能点**：`MD-07 research` 的**建行**归 F-11 `createResearch`（含 `research_no`/`opportunity_id`/`goal_id`/`goal_version_no`/`parent_research_no`/`start_task_id` 等启动快照与追问链字段），**内容填充**归 F-21 `updateResearchReport`（**只改 6 个正文/状态列 + `finished_at`**）。这样「出报告」这一步在结构上不可能改动启动快照与追问链；对应的 L3 反例（MD-07 FK）经**建行面**复现，填充面只验「研究不存在即拒」的前置守卫。配套：**承载硬红线文案的字段不参与禁词扫描**（如 `out_of_scope_note` 正文写着「活动配置/权益组合/预算与排期不在研究结论范围内」）——扫描对象只有七要素正文，且用例须放**豁免反例**（把禁词放进正文仍须被拒），防止豁免退化成「整表不扫」。
- **「纯读面编排器」范式（F-22）**：当功能点是「在已有产物上承接 / 消费」而非「产出新数据」时，本体**零写、只读、不调 LLM**——承接前后对原产物取快照**逐字节比对**做运行期自检（如 `original_preserved`），并显式声明「不否定原结论」（`negates_original_conclusion` 恒 false）。**跨模块读数优先走既有读面**：本模块**可新增一处跨模块只读面**（如 F-22 经 `../task-runner/step-plan.js#getTask` 读任务态），但**绝不新增跨模块写面**、不改上游 oracle；模块级硬红线要同补该只读面并写明「本模块仍不含任何跨模块写动作」。配套：**「未决 ≠ 沿用」**——判定是否复用既有依据时，**未声明变更 / 无法判定一律落到中间态并标 `llm_gated`**（既不沿用也不补查），只有「明确声明且可客观比对」才给沿用 / 补查的确定结论；**保守方向优先**（适用范围更窄沿用、更宽或抽不到时点一律补查）。

## 踩过的坑（本机实测）

- **`assert(someAsyncFn(...).length >= 2)` 忘了 `await`** → Promise 的 `.length` 是 `undefined`，断言**静默假失败**，排查成本极高。做法：async 结果先 `await` 进变量再断言，并把**实测值写进断言文案**（`实测 N 条`）。
- **「改前状态」必须在写之前取**：一串 `await` 之后再 `getTask` 拿到的是改后值。
- **静态扫描扫全文（含注释）**：`/\b(UPDATE|DELETE|DROP|ALTER|TRUNCATE)\b/` 会被**中文注释里的字面英文词**命中。散文里写「改行 / 删行类 SQL」；若该文件由自己写的用例扫描，就先 `stripComments` 再去扫。**同类推论（F-21 实测）**：断言要**精确到语句形态**——写「不写 `SELECT MAX`」而不是「不出现 `SELECT`」，否则注释里的字面词与编号计算里的 `Math.max` 都会命中。
- **「先执行后拒写」会留半截状态**：任何「任务态 / 归属校验」都要做成**前置守卫**，在执行与写入之前判，而不是等写到最后一步才抛。
- **引用自检的「重号」判定**：同一文件内 **≥2 个列表项以同一编号开头**即命中（跨文件引用同一编号不算）。所以同一编号的注意事项不要连着起 4 个列表项，改写成「门禁（F-26 相关）」「新登记 Q-12（未决，F-26 实施发现）」这类以主题开头的写法。
- **`Write` 重写中文长文档后自检 `&#xNNNN;` 实体转义残留**：`awk 'index($0,"&#x"){c++} END{print c+0}' 文件`，非 0 逐个修回。
- **阈值 / 数值入参的严数值化**：`Number(null)` 是 `0`、`Number("")` 是 `0`——若直接用 `Number.isFinite(Number(v))` 做校验，`composite_raw: null` 会被静默当成 0 放行（阈值判定就会得出错误的 `in_pool`）。做法：显式拒 `null`/`undefined`/`""`/布尔，再 `Number()` + `isFinite`。这条对「阈值、分数、计数」类入参一律适用。
- **写完必读回（别把草稿留在交付物里）**：本点实测在新写的写入面函数里留了一个**无意义的占位分支**（`if (!Number.isInteger(...) && false) { /* 占位 */ }`），跑测试全绿、只有人工回读才发现。做法：新文件交付前**通读一遍**，或用 `Grep` 搜 `TODO|占位|FIXME|&& false`。
- **HTTP 错误文案与状态码是耦合的**：`../api/index.js` 的 `errorResponse` **按文案关键词判状态码**（含「不在 / 不存在 / 未解析」等 → 400），故新增守卫若文案不含关键词会被归到 500（F-22 实测：三条守卫文案改成含「须为 hva_followup 任务」「须为 { from, to } 且 … 均可解析」「须为 … 之一」后才回到 400）。写新守卫文案时按此约定选词。
- **静态 import 计数会命中文件头注释里的示例**：用例里做「import 恰 N 条」断言时，若文件头文档卡写了 `from "./x.js"` 用法示例就会被误计——先 `stripComments(code)` 再抽 import。
- **前端调用点必须逐点对齐服务端返回结构（F-27 血泪）**：同一个域的写面返回形态**各不相同**——`registerGoal` → `{ goal, version }`、`saveGoalVersion` → **直接是版本行**、`fillGoalGap` → `{ gap, version, merged_field }`、`applyGoalVersion` → `{ applied_version_no, … , version }`、`runGoalCheckTask` → `{ task, check, gaps, all_gaps }`。页面按 `{ version }` 猜着读（`ver.version.version_no`）→ 属性读错**抛在渲染之前**，于是「库已改、界面没更新、后置动作没跑」——**一处读属性错误伪装成三类独立缺陷**（提示缺失 / 版本历史不刷新 / 待补项为 0），排查方向全被带偏。做法：写页面前先 `grep "^export async function"` + 读 return 行，把契约钉死；页面里的 `catch` 只在**动作边界**兜，别让它掩盖掉「契约读错」这种必现 bug。
- **保存流程里「后置动作自己落提示」会吃掉前一条提示**：保存成功后自动跑口径检查，检查的 `note()` 会立刻覆盖「已保存为 vX + 影响范围」，用户等于看不到保存结果（oracle 明确要求提示影响范围）。做法：后置步骤支持 `silent` 选项并**把文案 return 给调用方**，由主流程合成**一条**最终提示。
- **静态扫描断言要按「语句形态」，不是裸关键字**（第 30 条的加强版）：`\b(SELECT|DELETE|UPDATE …)\b` 会命中 CSS 元素选择器 `select`、HTML `<select>` 标签、JS `delete` 运算符；`/http/i` 会命中错误文案里的 `HTTP 500` 字样。判据改成**引号内的语句形态**（`SELECT … FROM` / `DELETE FROM` / `UPDATE x SET` …）与**带 scheme 的地址**（`https?://`），既保住判据又不误伤。同类：判断「前端不直连数据库」用 `env.DB` / `D1Database` / `.prepare(`，不要用裸 `SELECT`。
- **前端用例缺依赖要显式失败，不静默跳过**：仓库零构建、**无 `package.json`**，`jsdom` 只作测试期依赖（CI 用 `npm i --no-save jsdom`，装进仓库根 `node_modules` 即可，`createRequire` 自然解析得到、无需 `NODE_PATH`）。用例里 `require("jsdom")` 失败要 **打印安装命令并 `exit(1)`**——前端用例被跳过＝一条无人看守的静默洞。
- **目录级静态扫描的「排除执行器」规则不能写死自己的文件名（F-28 血泪）**：`frontend/test-f27.mjs` ③ 组扫描整个 `frontend/` 后 `if (/test-f27\.mjs$/.test(f)) continue`——只排自己。F-28 新增 `frontend/test-f28.mjs`（内含 `INSERT INTO`、`.prepare(`、`http://localhost`、`fetch(`）后，F-27 **一次红 6 条**（绝对地址 / 凭证 / D1 / SQL / mock / fetch 单点各 1），且报的是「前端受检文件」命中，极易误判成「新页面违规」。做法：**凡「扫一个目录里除我以外的所有文件」的用例，排除谓词一律按类别通配**（`/^test-f\d+\.mjs$/` 排执行器），并把「受检对象＝运行期产物」这层意图写进谓词旁注释。同理适用于「扫除我自己以外的所有同族文件」的任何断言。
- **选择器工具别把 `Element` 当 `dom` 传**：`q(dom, sel)` 若实现为 `dom.window.document.querySelector`，误传 `Element` 时抛 `Cannot read properties of undefined (reading 'document')`（报错点在工具函数、不在调用处，溯源绕一圈）。做法：`rootOf(x) = (x && x.window) ? x.window.document : x`，让 JSDOM / Document / Element 都能当 scope。
- **引用自检的解析基准是「本文件目录」和「仓库根」二者之一**：跨目录引用**要写相对仓库根的完整路径**（`frontend/pages/goal.html`）才命中；写目录内简写（`pages/goal.html`）会落到「软偏差·路径不精确」（不计失败但报噪）。**待建的产物无法避免软偏差**（文件还不存在），属正常项，建成即自消——不必为它加豁免条目。
- **「事实行优于状态列」：判断「某前置动作是否真的发生过」一律落在事实表上**：不要读状态列（可能被旁路写脏、或与事实不符），以**子表 / 事实表是否真有那一行**为准。本项目实测（F-29）：种子把 `OPP-010` / `OPP-012` 标成 `submitted`，但 `research_proposal` 里**没有**对应建议行；M1-F-17 的人工节点完成判据本就写的是「以 MD-12 有无真实建议行」（不看机会状态），前端 F-29 也照此实现——否则会谎报「该机会已提交过研究建议」。做法：**把这条反例写成用例主断言**（「状态为 submitted 但无建议行 → 不得谎报已提交」）。同类：判断任务是否真跑过看 `task` 行，不看目标状态位。
- **前端不复制第二份「校验口径」（规则在服务端时）**：校验规则（关键词表 / 阈值 / 提示语）的唯一真源在服务端时，页面应**调服务端的检查接口**并把返回值原样呈现，而不是在前端再写一份正则。落地三件套：① 页面只渲染服务端返回的 `missing[]` / `hint`；② 用例**静态断言页面不出现那份规则的「正则字面」**（含 `|` 的备选式，如 `人群|用户|新客|客群`）与阈值数字，也不硬编码提示语；③ 加**「不误报」反例**（输入已满足某条时不得点名该条）。注意判据用**正则字面而非单个词**——原型钉死的 placeholder 里出现「搜索 / 人群」这类词是允许的，不算复制口径。
- **静态谓词的「类别通配」要覆盖未来编号**：`/test-f2[0-9]\.mjs$/` 是「看起来通配、实则只到 29」——`test-f30.mjs` 不匹配，于是未来每加一个执行器都会打红既有用例（F-28 实际踩到）。写类别通配用 `\d+`（`/^test-f\d+\.mjs$/`），别用 `[0-9]` 这种单字符类；确要限上限就把理由写进注释。
- **改 `db/seed` 种子的两条硬纪律（2026-09-20 血泪）**：① **生成器与已验证 SQL 会不同步**——`generate_mock.py` 是「运行即**全量**重写 `0001_mock.sql`」，人工在 SQL 上做的修正若**没同步回生成器**，重跑会把那些修正**静默回退**（实测：重跑后 `gap_rule` 的规范化字段名被回退成别名、冲掉 Q-13 已决①，并改了 T-1023 父任务与 LK-OR-001 的关系语义——后者还是跨枚举误用，`related_update` 属 `EVIDENCE_LINK_KIND` 而非 `OPP_RELATION`）。做法：改种子前先把人工修正**同步回生成器**再重跑，重跑后**必须 `diff` 核对只应出现预期差异**（与改前版本比对，逐表确认变更范围）。② **改种子后必须跑全量 32 套件回归**——只跑「相关」套件会漏掉跨表关联影响（实测：Q-16 只跑 F-16/F-17，漏掉 F-01 因 `gap_rule` 别名而失败的 `alias_fields` 断言，隔了一整轮才暴露）。
- **`grep … | head -N` 截断会漏掉同步目标（2026-09-20 血泪）**：同步下游钉版引用时，用 `grep -rln "关键词" | head -20` 列文件会被截断——实测漏掉 `db/README.md` 等 3 个文件里的 5 处「TS-11 仍待裁决」，改完以为齐了其实没齐。做法：凡「全量」语义的操作**禁止 head 截断**；先 `grep -c` 计总数确认规模，或直接按**关键词不截断全扫**（`grep -rn "TS-11"`）。同类推论：**复核也要全量**——改完用「排除有意保留项」的谓词（如 `grep -v "~~"`）验证真残留为 0，而不是抽查。
- **未决项不只挂三张清单，ADR 也会内嵌**：扫「待确认」若只扫 `schema.md` §12 / `external-deps.md` §7 / `tech-stack.md` §8 会漏。实测 `ADR-003` §7 两条 ⬜ **不在任何一张表里**，而 ADR 自己写明「必须在下游写入侧实现前关闭」，写入侧却已落地 → 真空缺。做法：按 `⬜|⏳|待确认|待裁决` **全仓扫**（含 `docs/07-decisions/`），并优先看那些「写明必须在某动作前关闭」的项——它们最容易变成已敞口却无人发现的缺口。
- **bump 版本后同步下游，钉版引用要分两类处理**：**「现状声明」**（如「已建 v1.2」「✅ 已有 v1.2」）跟着改成新版本；**「历史事实」**（如「2026-09-19 回填至 v1.2」）**保留旧版本号**，改成新版本会让史实失真。已决项用 `~~划掉~~ → 已决（日期）` 保留痕迹，不要直接删掉旧表述（删了就看不出曾经待决）。另外「待确认条数」这类汇总数字要同步递减（实测 §8 由 13 条减为 12 条）。

- **修完 bug 要「反证」：注入错误值，确认新断言真的会红**（2026-09-20 血泪）：收编 `llm-client.js` 时写了「执行过工具后正常结束 → `stopped_by` 须为 `model_end`」的断言，跑出 56 全绿。但我**回滚修复后测试仍然全绿**——因为真正的修复是另一处（把赋值移出循环），回滚 A 处根本不影响结果。若就此收工，这条断言能否防住回归**完全未知**。做法：临时把正确值改成错误值（如 `stopped_by: "model_end"` → `"max_rounds"`）再跑一次，**必须看到断言变红**，然后恢复。**由绿变红才证明断言咬得住**。另注：本 shell 下 `sed -i '' 's/x/y/' file` 的参数会被吞（`s/x/y/` 被当成文件名报 No such file），改用 `node -e "…readFileSync…replace…writeFileSync"` 做临时替换更可控（配合先 `cp` 备份再恢复）。

- **工作区会被「另一个进程」并发修改，提交前必须逐个核对改动来源**（2026-09-20，已三次复现）：`git status` 出现过**本会话从未编辑过**的文件改动——先是 `wrangler.toml` + `server/api/index.js` + 新增 `llm-client.js`（Workers AI 接入试验，222 行、含具体模型 ID），收编提交后又冒出 `discovery.js` +295 行（接入 LLM + 跨模块写面）与 `agent.md` +14。特征：来源不明、未测试未登记。做法：① 提交前**逐文件确认「这是我改的吗」**，不是就**单独挑出不夹带**（`git add` 只列自己的文件）；② 向用户报告并等裁决，不擅自收编或删除；③ 已确认的错误要修（如 `[[ai]]` 被写成 `[ai]`，**修完还会被改回**，须复核时间戳）。另：收编这类游离改动时它们是**不属于任何分支**的工作区内容，只能就地提交，提交前用 `git status --short` 圈定范围。

- **「未决」有两种标记，只数 ⬜ 会少算——「有 demo 占位值」同样是未关闭**（2026-09-20 血泪）：`external-deps.md` §7 的末列是「demo 占位」。除 `⬜ 正文留空`（11 条）外，**带 `*` 的 demo 占位值**（T-01~T-05：真实工具名 / 条件字段语法 / 历史深度 / 权限边界 / 返回结构）**同样是未关闭**——真值没拿到，只是用 demo 顶着。**危害更大**：demo 让链路跑得通，形成「假性就绪」，比空白更容易被误认为已就绪。实测只按 ⬜ 计数得 11，真实为 **16 条**。做法：统计未决一律**两种标记都算**，并按「是否已有可运行的占位」分级——有占位的要标注「假性就绪」。同理适用于任何「用 mock/demo 顶着」的登记项。
