## 打开方式与存储说明

直接双击 `prototype/index.html` 即可，侧栏可在六个页面间切换（导航链接以 `prototype/` 根目录为基准，运行中按当前页位置补前缀）。

原型期用户动作写在本机 `localStorage`（key：`jd_growth_prototype_store_v2`），只影响本机，不提供页面内的重置入口——需要清空时在浏览器开发者工具里删掉该 key 即可。

以 `file://` 打开时若浏览器禁用了 `localStorage`，顶栏会显示「存储降级」提示——此时页面照常可用，且**新提交的任务会通过 URL 参数带入任务页**，跨页联动不会断。想获得完整持久化体验，在 `prototype/` 下执行：

```
python3 -m http.server 8899 --bind 127.0.0.1
```

| 项 | 实现 | 后续真实运行时 |
| ---- | ---- | ---- |

## 先后运行关系（准入）与未读绿点

原型里每一步都不是孤立的：**上一个动作没做，下一个页面就不成立**。这条链摆在页面上，也写进了代码（`assets/app.js`）。

```
① 目标配置（F-27 保存六要素）
      │  未保存 / 只配置未应用 → 机会列表不放行
      ▼
② 应用配置 ＝ 执行一次机会发现（M1-F-02 → M3，F-27 页按钮）
      │  跑过（有历史产出，或本次正在运行）→ 放行
      ▼
③ 机会列表可进入（F-28）→ 提交研究建议（F-29）→ 研究结果（F-30）→ 追问（F-31）
```

| 机制 | 判定 | 落地位置 |
| ---- | ---- | ---- |
| 运行链状态 | `U.runState(goalId)` 给出 `no-run` / `queued` / `has-data` 三态 | `assets/app.js` |
| 门禁 | `U.gateOf(page)`：F-28 在 `no-run` 时 `locked`，侧栏该项置灰标「未运行」且点击不跳转，页内换成门禁态（不是「暂无机会」空态），并给出「去目标配置执行机会发现」的唯一出口 | `assets/app.js` + `opportunities.html` |
| 运行链状态条 | 三个页面（总览 / 目标配置 / 机会列表）页内显示 ① ② ③ 走到哪一步；`queued` 时整条变蓝并标「运行中」 | `.chain-bar` |
| 未读绿点 | 运行动作产生新任务/新产出时打点：F-27「应用配置」→ 机会列表；F-27「保存为新版本」→ 目标配置；F-29 提交研究建议 → 任务与状态；F-31 追问 → 任务与状态 + 研究结果。**点击侧栏对应项即清除** | `U.markUnread` / `U.clearUnread` |

绿点按目标分别记账（`navUnread[goalId][page]`），切目标不会串；`no-run` 的目标也不会把别的目标的绿点带出来。

**为什么把这三件事放进 `app.js`**：目标解析（`?goal` 参数 → 本机 `applied` → `DB.applied` → 默认目标，候选集合含本机新建目标）、六要素与版本（`goalFields` / `goalVer` 覆盖 mock 原值）、任务归属（`goalTasks`：认任务自身的 `goal` 字段，并能从 `ref` 里回认目标 ID）过去在四个页面各写一遍，出现过「总览认新建目标、任务页不认」「同一目标在两页显示不同版本」「同一概念两页算出不同的数」这类互相打脸。现在四页读同一份实现——**凡是两页都要显示的同一个数，就必须来自同一个函数**。

## 原型期内刻意保留的硬红线

- 指标口径缺失时只列待补项，**不替业务方定义指标**
- 证据一律带来源、查询条件、信息时点、适用范围；新证据不覆盖旧依据
- HVA 研究完成前一律称「候选行为」
- 运行失败 / 查询失败只标「受限」，**不作为否定结论**
- 两阶段之间保留人工节点，无自动交接、无自动立项
