## 1. 模块目标与定位

M3 是第一阶段研究 Agent：围绕业务目标寻找潜在机会与问题——找线索、查证现象、整理值得关注的问题，止于"机会＋初步依据"，供人选择。**是否存在值得关注的候选 HVA，要等 PM 提出研究问题后由第二阶段（M4）分析**。本模块产出"机会"而非"结论"，不下 HVA 判断。

## 1.1 领域能力定义（agent.md · business-rules.md · Skill 清单）

> 本模块的运行期领域能力由三部分构成：**角色指令（agent.md）**定义"你是谁"、**公共业务指令（business-rules.md）**是两 Agent 共用的行为边界、**Skill 清单**是 Agent 可调用的能力单元（每个 Skill 对应 §3 的一个或多个功能点）。来源文件：`agent.md`（机会发现 Agent 角色段）、`business-rules.md`（公共业务指令）、Skill 注册见 `MD-14 skill_registry`（S-A1~S-A4，Q-07 已决：S-A1＝`clue-scan`）。

### 1.1.1 角色指令（agent.md · 机会发现 Agent）

- **职责**：京东超市用户增长机会发现研究员，围绕业务目标寻找值得进一步研究的现象。
- **输入**：业务目标与口径、业务背景与约束、触点清单、可用来源与工具说明、已有机会摘要、相关历史研究。
- **工作方式**：围绕目标决定先查什么 → 请求工具查询（经工具执行程序 M5）→ 对返回结果做基础查证（来源 / 适用范围 / 时点 / 已有机会 / 缺口 五查）→ 线索关联到具体人群或旅程环节。
- **输出**：机会记录（六要素）＋初步证据；或检查范围与信息缺口。
- **结束条件**：形成机会与初步依据，或说明本轮未发现足够依据。对现象的解释一律标明"尚未验证"。

### 1.1.2 公共业务指令（business-rules.md · 两 Agent 共用）

> 作为公共业务指令由运行程序（M1）加载，机会发现 Agent 与 HVA 分析 Agent 共同遵守。

- 关键发现需要关联实际取得的证据；
- 初步解释、产品假设与研究判断分别标明性质；
- 业务范围、证据要求、信息使用边界和输出原则；
- 查询必须经工具执行程序，禁止以模型预期内容代替查询结果；权限不足或失败时保留原因并说明受限；
- 引用任何证据必须带来源系统、查询条件、信息时点与适用范围——作为公共业务指令由运行程序加载，两 Agent 共同遵守；
- 不替业务方定义指标口径；口径不清时列出待补项；
- 研究输出止于"有依据的判断＋限制＋改善方向"，不输出活动配置、权益组合、预算与排期；
- 不调用任何面向生产环境的写接口（硬红线）。

## 2. 范围

**In scope**：F-13~F-17（角色指令配置、围绕目标寻找线索、基础查证、机会形成与去重、两步衔接）。
**Out of scope**：HVA 分析（M4）、查询执行（M5，本模块只发起查询请求、由 M5 执行）、前端展示（M6）、目标与任务调度（M1）。

## 3. 功能需求

### F-13 角色指令配置

- **功能描述**（继承 BRD §4）：agent.md 定义"你是谁"：本阶段职责、输入、输出与结束条件；与 Skill（能消费什么）、程序（能干什么）一起构成领域能力。
- **输入 → 输出**：— → agent.md（discovery-agent）。
- **验收要点**：结束条件二选一——形成机会与初步依据 / 说明本轮未发现足够依据。
- **关联 schema**：`MD-13 agent_profile`（主键 `profile_id=AGP-DISC`、对外 `agent_code=discovery-agent`，存角色指令登记与版本引用）、`MD-14 skill_registry`（Skill 能力登记；Q-07 已决 2026-09-19，`S-A1`=clue-scan 已种，映射确认）。
- **关联技术栈**：Agent 推理来源＝Workers AI（`tech-stack.md` DS-02）；指令本体为仓库文件（`agent-runtime/`），D1 存登记与版本引用。
- **依赖与衔接**：被 M1 F-02 在发现任务中加载。

### F-14 围绕目标寻找线索

- **功能描述**（继承 BRD §4）：接收目标、背景、可用来源、历史研究，围绕目标决定先查看哪些信息。线索来源：经营表现变化、人群已有行为差异、用户反馈、新的业务信息。线索必须关联到具体人群或用户旅程：**记录"谁在什么环节遇到了什么现象"，而非仅罗列一组变化**。
- **输入 → 输出**：目标＋背景 → 关联人群 / 旅程的线索。
- **验收要点**：线索对人群差异的使用停留在发现现象与基础查证，不提前下 HVA 判断。
- **关联外部依赖**：数据源＝CDP / HJE / MKT / ACT（`external-deps.md` §1 F-14 行）。
- **关联工具**：TOL-01 cdp.crowd.query、TOL-02 cdp.tag.distribution、TOL-04 hje.traffic.entry、TOL-05 hje.slot.exposure、TOL-06 hje.path.conversion 等（§5）。
- **依赖与衔接**：消费 M2 背景/来源/历史；发起查询经 M5。

### F-15 基础查证

- **功能描述**（继承 BRD §4）：Agent 选择需核对的信息 → 程序实际执行查询或必要基础统计 → 结果及来源返回。五项检查：来源（哪份资料哪次查询）/ 适用范围（人群、渠道、旅程环节是否对应当前目标）/ 信息时点（业务条件是否已变化）/ 已有机会（是否记录过相同问题）/ 信息缺口（还缺什么、缺失影响哪项判断）。
- **输入 → 输出**：线索 → 查证后的初步依据。
- **验收要点**：对现象的解释必须标明尚未验证的部分；支持"值得进一步研究"，不给完整人群对照和 HVA 结论。
- **关联 schema**：`CFG-05 gap_rule`（口径检查规则，落库五查口径）。
- **关联外部依赖**：数据源＝CDP / HJE / PIM（+ 必要基础统计）（§1 F-15 行）。
- **依赖与衔接**：查询经 M5 执行并落 `EXT-01 query_record` → `EXT-02 evidence`（M2 F-09）。

### F-16 机会形成与去重

- **功能描述**（继承 BRD §4）：依据足够 → 保存机会与初步证据；相同问题关联更新；依据不足 → 保存检查范围与信息缺口，允许本轮不产生新机会。
- **输入 → 输出**：查证结果 → 机会记录或缺口记录。
- **验收要点**：没有足够依据也是合法产出（对应领域问题的优化方向）。
- **关联 schema**：`MD-06 opportunity`（机会六要素写入）、`LNK-03 opportunity_relation`（相同问题关联更新）。
- **关联决策**：机会六要素必填与未知项二态见 `ADR-003`（Q-05 裁决）。
- **依赖与衔接**：写入 M2；供 M1 F-03 人工节点选择。

### F-17 两步衔接

- **功能描述**（继承 BRD §4）：机会＋初步依据作为 PM 输入的前提；拿到结果之后的对话过程作为第二个 Agent 的输入；必要信息可能需要 Agent 反过来问 PM。
- **输入 → 输出**：机会记录 → PM 决策上下文。
- **验收要点**：衔接经人工节点，不自动交接（见 M1 F-03/F-04）。
- **依赖与衔接**：交付 M1 F-03（研究建议管理）；触发 M4 第二阶段。

## 4. 关键约束与红线

1. **止于机会**：本阶段只产出"机会＋初步依据"，不下 HVA 判断；是否值得关注候选 HVA 由 M4 在 PM 提问后分析。
2. **线索须关联人群/旅程**：禁止仅罗列一组变化。
3. **解释须标未验证部分**：支持"值得进一步研究"，不给完整人群对照与 HVA 结论。
4. **人工节点不自动交接**：机会→研究建议→HVA 任务之间必须经 PM（BRD §3.1、M1 F-03）。
5. **白盒原则**：F-13~F-17 逐点验收、双向引用。

## 5. 验收总则（模块级，承接 BRD §7）

- 线索关联具体人群/旅程；查证五项检查齐全且缺口标注。
- 机会六要素齐全、未知项二态正确；无足够依据时合法产出缺口记录。
- 证据可回查（来源/条件/时点/适用范围）。
