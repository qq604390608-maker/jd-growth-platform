## 1. 模块目标与定位

M5 是平台的**查询执行与留痕层**：检查权限与调用条件、查询来源或执行分析、返回真实结果、保存查询依据。所有外部接口均已 MCP 化，tools 注册到 Agent，执行是纯程序。本模块是"真实查询结果"的唯一来源——**杜绝用模型预期替代查询结果**。

## 2. 范围

**In scope**：F-23~F-26（工具注册与权限检查、查询执行与真实返回、查询记录保存、失败重试与受限返回）。
**Out of scope**：研究判断（M3/M4）、目标与任务调度（M1）、前端展示（M6）。外部验证的"执行与效果计算"由业务工作完成，本模块只登记结果（EXT-03）。

## 3. 功能需求

### F-23 工具注册与权限检查

- **功能描述**（继承 BRD §4）：五类系统的 MCP 工具注册到 Agent；每次请求先检查当前任务权限与调用条件（自循环步骤）。
- **输入 → 输出**：Agent 请求 → 权限判定。
- **验收要点**：权限分支互斥——允许 / 不允许，不允许时保存原因并返回受限原因。
- **关联 schema**：`CFG-02 tool_registry`（工具注册，12 个 `tool_code`）、`CFG-03 tool_permission`（任务权限与调用条件，按任务×工具授权）。
- **关联外部依赖**：12 个工具 TOL-01~12（`external-deps.md` §5）：CDP（TOL-01/02/03）、HJE（TOL-04/05/06）、PIM（TOL-07/08）、MKT（TOL-09/10）、ACT（TOL-11 降级 / TOL-12 不存在）。
- **依赖与衔接**：被 M1 F-02/F-04 调度时按任务授权；被 M3/M4 查询请求触发。

### F-24 查询执行与真实返回

- **功能描述**（继承 BRD §4）：访问 CDP（用户标签）/ 黄金眼（线上流量）/ 商品中台（超市商品）/ 营销中台（权益）/ 活动报名系统（活动），返回实际结果及限制；失败返回具体原因。
- **输入 → 输出**：查询条件 → 实际结果或失败信息。
- **验收要点**：**不能用模型预期的内容代替查询结果**；返回内容保留查询条件、来源、时点、限制。
- **关联外部依赖**：数据源＝CDP / 黄金眼 / 商品中台 / 营销中台 / 活动报名系统 五类全体（§1 F-24 行）；各系统 `can`/`cannot`/`status` 与缺口语义见 §2（P0 阻断 CDP/黄金眼、P1 削弱 商品中台/营销中台、P2 降级 活动报名系统）。
- **关联技术栈**：查询经自建 MCP 客户端（DS-06）执行。
- **依赖与衔接**：结果交付 M3/M4 并转 M2 `EXT-02 evidence`（F-09）。

### F-25 查询记录保存

- **功能描述**（继承 BRD §4）：每次执行把条件、来源、时点、结果或失败原因写入任务记录，同时供共享上下文作为证据。
- **输入 → 输出**：执行过程 → 查询记录。
- **验收要点**：失败也留痕；记录可回查。
- **关联 schema**：`EXT-01 query_record`（查询记录：条件/来源/时点/结果或失败原因）。
- **依赖与衔接**：被 M1 F-06 聚合进任务记录；供 M2 F-09 转证据。

### F-26 失败重试与受限返回

- **功能描述**（继承 BRD §4）：调用失败按配置限制重试（代码驱动的重启机制：失败记录 → 重新调起接口，把任务完整执行）；持续失败暂停受影响研究并保留已完成部分。
- **输入 → 输出**：失败事件 → 重试 / 暂停 / 受限返回。
- **验收要点**：重试是代码逻辑不是 AI 决策；实在卡死保留状态停止。
- **关联 schema**：`EXT-01 query_record`（失败原因留痕）、`PD-03 task_block`（受阻记录，与 M1 F-06 协同）。
- **关联技术栈**：重试＝代码逻辑（DS-03 状态机），与 M1 F-06 一致。
- **依赖与衔接**：与 M1 F-06 共用状态机口径；与 M6 F-32 状态展示一致。

## 4. 关键约束与红线

1. **真实返回硬红线**：绝不用模型预期替代查询结果；返回须带查询条件/来源/时点/限制（BRD §5.3、§7 第 3 条）。
2. **工具存在性如实登记**：TOL-12 是"不存在"而非"待接入"，须如实登记（`external-deps.md` §5 脚注）——否则 Agent 会误判缺口性质。
3. **失败也留痕**：失败原因写入 `EXT-01`；运行失败不作为否定 HVA 的依据（BRD §7 第 4 条）。
4. **生产环境零写操作**：本模块只读查询，绝不写生产数据（BRD §5.3）。
5. **白盒原则**：F-23~F-26 逐点验收、双向引用。

## 5. 验收总则（模块级，承接 BRD §7）

- 每次查询（含失败）可回查：条件/来源/时点/结果或原因。
- 权限分支互斥，受限原因可返回。
- 重试为代码逻辑，卡死保留状态停止；状态口径与 M1 F-06 / M6 F-32 一致。

## 6. 待确认项（来自 external-deps §7，关闭前不宜视为可实施）

- T-01 真实 MCP 工具名与清单是否与我方设计的 12 个工具一致。
- T-06 黄金眼 / 商品中台 / 营销中台的失败语义（原型无失败实例）。
- T-07 活动报名系统降级是常态还是临时（`status=degraded` 判定依据）。
- T-08 活动报名系统是否确认无用户参与明细（若开放，TOL-12 须重评估）。
- T-22 MCP 工具调用协议版本与工具描述格式。
