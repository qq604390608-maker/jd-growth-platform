## 1. 模块目标与定位

M1 是平台的**组织者 / 调度层**：负责研究目标与口径的版本化管理、两阶段研究任务的创建与调度、人工节点的研究建议管理、追问与版本派生、以及任务全生命周期的记录与异常恢复。它把"目标 → 发现 → 人工节点 → HVA 研究 → 结果 → 追问"这条主线串起来，自身不做研究判断，只做确定性的调度、存储与状态流转。

## 2. 范围

**In scope**：F-01~F-06（目标登记与口径、发现任务调度、研究建议管理、HVA 任务调度、追问与版本管理、任务记录与异常恢复）。
**Out of scope**：Agent 的研究判断（M3/M4）、外部查询执行（M5）、前端展示（M6）、共享上下文的内容组织（M2，M1 仅消费上下文注入结果）。具体排除项见 BRD §5.2（活动玩法与权益配置、收益测算与立项评审、生产环境写操作、自动交接与自动立项等）。

## 3. 功能需求

### F-01 研究目标登记与口径管理

- **功能描述**（继承 BRD §4）：登记业务方提供的目标六要素（业务目标、指标口径、业务范围、关注时段、已知约束、提供方与材料）；口径不清时列出缺少信息由业务方补充；Agent 和 PM 不替业务方另定指标定义；目标更新后保存变化，已有研究保留启动时的目标与范围，新目标建新研究版本，不混两个时期的判断。
- **输入 → 输出**：目标材料 → 结构化、版本化的研究目标。
- **验收要点**：① 同一研究不因目标中途更新被悄悄替换；② 待补项清晰列给业务方；③ 版本切换不污染历史研究的口径快照。
- **关联 schema**：`MD-01 research_goal`（目标主体）、`MD-02 research_goal_version`（六要素快照，每次变更落新版本）、`MD-03 goal_material`（材料附件引用）、`PD-04 goal_gap`（口径待补项，由 F-01 维护）。
- **关联决策**：目标版本化规则见 `ADR-001`（业务背景不与目标版本联动）；六要素必填与变更见 `schema.md` §12 Q-05。
- **依赖与衔接**：上游＝业务方目标；下游＝F-02 调度、F-03 研究建议、M3/M4 消费目标与版本。

### F-02 机会发现任务调度

- **功能描述**（继承 BRD §4）：到达运行条件（运行频率 / 时长 / 调用限制按业务需要配置）时创建发现任务，准备一阶段上下文（目标、范围、背景、相关历史、能力说明），调用机会发现 Agent。
- **输入 → 输出**：业务关注配置 → 发现任务＋Agent 启动。
- **验收要点**：任务程序决定何时启动；Agent 只在任务内选择分析方法，不在任务外自发行动。
- **关联 schema**：`PD-01 task`（任务主记录，`task_type=discovery`）、`PD-02 task_step`（步骤进度）、`CFG-04 run_policy`（运行频率 / 时长 / 调用限制）、`CFG-06 context_template` + `PD-06 context_injection`（一阶段上下文）。
- **关联技术栈**：调度由 Cron Triggers + Queues + 自建状态机实现（`tech-stack.md` DS-03）。
- **依赖与衔接**：调用 M3（机会发现 Agent）；上下文来自 M2。

### F-03 研究建议管理（人工节点）

- **功能描述**（继承 BRD §4）：PM 选机会＋提研究问题（必需），可补候选行为假设、人群限制（可选）；平台检查并保存；问题不明确只补充要查清的内容，不要求重填已有材料；同一份研究建议重复提交不重复启动相同任务。
- **输入 → 输出**：选定机会＋研究问题 → 保存的研究建议记录。
- **验收要点**：建议与机会版本关联；重复提交幂等（不重复启动相同任务）。
- **关联 schema**：`MD-12 research_proposal`（研究建议主表，关联机会版本与研究问题、可选假设/人群限制）。
- **关联决策**：人工节点是 M3→M4 之间必需节点，不自动交接（`BRD.md` §3.1、M1 关键规则）。
- **依赖与衔接**：上游＝M3 产出的机会（MD-06）；下游＝F-04 调度 HVA 任务。

### F-04 HVA 研究任务调度

- **功能描述**（继承 BRD §4）：研究建议提交后，组织二阶段上下文（所选机会及版本、产品问题、可选假设、关联目标与证据、相关历史研究），调用 HVA 分析 Agent。
- **输入 → 输出**：建议记录 → HVA 任务＋Agent 启动。
- **验收要点**：第二阶段启动时点＝建议提交；已允许的查询工具按任务规则执行。
- **关联 schema**：`PD-01 task`（`task_type=hva_research` / `hva_followup`）、`PD-06 context_injection`（二阶段上下文，含机会/问题/证据/历史）、`CFG-03 tool_permission`（按任务授权）。
- **依赖与衔接**：调用 M4（HVA 分析 Agent）；上下文来自 M2；工具权限来自 M5。

### F-05 追问与版本管理

- **功能描述**（继承 BRD §4）：PM 在已有研究上提新问题 → 关联原研究建立新任务；问题或范围修改后形成新版本，已有任务继续使用启动时的版本。
- **输入 → 输出**：新问题＋原研究 → 新研究任务（关联原研究）。
- **验收要点**：原研究结果与依据继续保留；新旧版本不混。
- **关联 schema**：`PD-01 task`（`parent_task_id` 自引用，追问任务挂原任务）、`PD-07 followup_message`（追问对话消息）、`MD-02 research_goal_version`（问题/范围变更落新版本）。
- **依赖与衔接**：上游＝M4 研究结果（MD-07）；下游＝再次调用 M4（F-22 承接）。

### F-06 任务记录与异常恢复

- **功能描述**（继承 BRD §4）：每次任务保存启动依据、指令与能力版本、查询及返回记录、已形成内容、当前状态；失败按配置限制重试（代码驱动重跑），持续失败暂停受影响研究，真卡死保留已完成部分停止；**运行失败本身不能作为否定某项 HVA 的研究依据**；研究内容与运行状态分别记录；任务受阻后定位缺口、保留已完成工作。
- **输入 → 输出**：任务执行过程 → 任务记录＋状态机流转。
- **验收要点**：状态机；停止状态不自动重启；研究内容与运行状态分别记录。
- **关联 schema**：`PD-01 task`（状态字段）、`PD-02 task_step`（步骤）、`PD-03 task_block`（受阻记录，含缺口与已完成部分）、`PD-05 opportunity_status_log`（机会状态变更）、`EXT-01 query_record`（查询及返回记录，由 M5 写入，本模块聚合）。
- **关联技术栈**：重试＝代码逻辑非 AI 决策（`tech-stack.md` DS-03；与 M5 F-26 一致）。
- **任务受阻处理矩阵 / 状态流**：直接引用 BRD §4 F-06 两张表（受阻矩阵、状态流），本模块须逐条实现。
- **依赖与衔接**：聚合 M3/M4/M5 的运行产物；状态机口径须与 M6 F-32 一致。

## 4. 关键约束与红线

1. **白盒原则**：F-01~F-06 逐点开发、逐点验收，每份产物双向引用。
2. **人工节点不可越权**：M3→M4 之间必须由 PM 选机会、提问题，平台不自动交接（见 BRD §3.1）。
3. **版本隔离**：目标与研究版本变更须落新版本，历史快照只读、不被覆盖。
4. **失败不污染结论**：运行失败/查询失败不作为否定 HVA 的依据（BRD §7 第 4 条）。
5. **生产环境零写操作**：本模块调度的查询经 M5 执行，绝不写生产数据（BRD §5.3）。

## 5. 验收总则（模块级，承接 BRD §7）

- 以功能点为单位逐点验收；每份产物建立双向引用、拒绝孤儿文件。
- 目标/研究版本切换的「不混期」须有回归验证。
- 任务状态机须与 M6 F-32 展示口径一致。
- 重复提交（F-03）须幂等。
