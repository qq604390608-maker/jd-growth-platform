## 1. 业务痛点与动机（出处：BRD §1）

京东超市运营与产品经理挖掘用户增长机会时，依赖一套前置调研流程：**找信息 → 找问题 → 拆旅程 → 比标杆 → 定关键行为**。

当前该流程的痛点（照录 BRD §1）：

- **缺乏系统化沉淀**——信息分散、证据不可回查；
- **两阶段研究缺乏衔接**——机会发现与 HVA 分析各干各的，重复调研频发；
- 结果：机会挖掘质量**依赖个人经验**。

## 2. 平台定位：建议型系统（出处：BRD §1 / §2.2）

平台把上述流程沉淀为系统化能力，形态是「**半 AI、半流程、半系统化**」：

| 角色 | 承担什么 |
| ---- | ---- |
| **AI（两个 Agent）** | 研究发现与判断**建议**（M3 机会发现 / M4 HVA 分析） |
| **程序（M1/M2/M5）** | 确定性的调度、存储与执行；所有外部查询经 MCP 工具**真实返回、失败留痕** |
| **人（PM 人工节点）** | 机会发现与 HVA 分析之间**选机会、提研究问题**（不自动交接） |

三条目标（照录 BRD §2.1）：全链路系统化、过程留痕证据可回溯；两阶段共享上下文人工衔接避免重复研究；外部查询真实返回、杜绝「用模型预期替代查询结果」。

**不做什么**（定位边界，出处 BRD §2.2）：平台产出机会与研究成果**供人决策**，**不自动立项、不自动执行业务动作**。

## 3. 服务对象与适用范围（出处：BRD 文档卡 / ADR-001）

- 服务对象：**京东超市运营同学 ＋ 产品经理**；
- 适用范围：**京东超市单一频道，不做全局**（ADR-001 同口径）。

## 4. 核心流程主线（出处：BRD §3 / §3.1）

```
业务方目标 ──► M1 登记（F-01）
                │
                ▼

                │

                │
                ▼

```

## 5. 范围边界（出处：BRD §5，逐条照录）

**in scope**：F-01~F-32 覆盖「目标 → 发现 → 人工节点 → HVA 研究 → 结果 → 追问」全链路 ＋ 五系统查询留痕。

**out of scope（防扩展、防追加）**：

- 活动玩法与权益配置
- 收益测算与立项评审（用研究结果另行开展）
- 评论区 / 客诉反馈分析（迭代方向）
- 生产环境任何写操作
- 京东全局算法因子
- 自动交接与自动立项
