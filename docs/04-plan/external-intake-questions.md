## 0. 怎么用

| 步骤 | 动作 |
| ---- | ---- |
| 1 | **按组转发**：A 组 → 外部系统对接方；B 组 → PM；C 组 → 技术方。每组可独立转发，不必等别组 |

| 3 | 回填 `external-deps.md` §7 正文，把该行状态翻 ✅；若该行原本是 demo 占位，同时**撤掉 demo 值** |
| 4 | 若答案显示「当前库结构承载不了」（如失败类型不止一种），**先登记 Q-xx 挂 `schema.md` §12**，不要先改代码 |

> **为什么要单独出这份稿**：§7 的表格行只有「事项 / 谁提供 / 阻塞什么 / demo 占位」四列，**没有可直接转发的问句**。对方拿到「失败语义」这四个字并不知道该答什么——提问单的作用是把「登记项」翻译成「对方能答的问题」，并提前说明「答什么算合格」，减少往返。

### T-06 · 黄金眼 / 商品中台 / 营销中台的失败语义

> **提问原话**：当我们调用贵方接口失败时，会返回哪些**不同类型的失败**？请给一份失败类型清单，并逐项说明：① 失败时返回的字段与取值；② 该类型**是否值得重试**（重试能成功 / 重试也不会成功）；③ 如果是「无权限 / 未开通」，是否会在正常响应里以「部分字段为空」的形式返回，而不是报错？

| 项 | 内容 |
| ---- | ---- |
| 为什么需要 | F-26 的重试是**代码逻辑、不是 AI 决策**（验收要点原话）。必须能区分「限流 / 超时」（重试有意义）与「参数错 / 无权限」（重试无意义），否则要么无效重试打满配额，要么该重试的没重试 |
| 合格回答 | 失败类型清单（≥2 项）+ 每类的判定字段 + 每类的重试建议 |
| ⚠️ 可能牵动库结构 | 当前 `EXT-01.result_status` 的值域**只有 `ok` / `fail` 两值**（`dict:QUERY_STATUS`，见种子 `DI-048`/`DI-049`）。**若失败有多种语义，当前结构承载不了**，需在值域上扩或增加失败类型字段 → 先登记 Q-xx，不要先改代码 |
| 不答的后果 | F-26 只能把所有失败当同一类处理：要么对不可恢复的失败空转重试，要么把可恢复的失败直接判死 |
| 阻塞 | F-26 失败重试与受限返回 |

| 项 | 内容 |

| 不答的后果 | 降级被当成完整数据使用 → 结论建立在残缺数据上却不自知；或把常态降级误判为故障、白白停用该源 |
| 阻塞 | F-08 可用性登记、依赖强度分级 |

> **提问原话**：① 贵方接口返回结果的**最小样本量**是否有阈值（低于阈值会怎样）？② 结果集过大时是否**会自动截断**？若会，截断发生在第多少条，响应里**有没有标识告诉我们被截断了**？

| 项 | 内容 |
| ---- | ---- |

- **回填时若牵动种子**：改种子前必须先把人工修正**同步回 `db/seed/generate_mock.py`** 再重跑，重跑后 `diff` 核对只出现预期差异；改完跑**全量套件回归**（2026-09-20 血泪：只跑相关套件漏掉了跨表影响）。
- **时效**：本提问单基于 2026-09-20 的 §7 状态（16 条未决 + 3 条存疑）。若 §7 条数变化，本文件须同步，否则提问单会与清单脱节。
