## 一、拍板类（8 条）

### TS-12（策略面）· 哪些列表列需要按拼音排序？

- **拍板人**：PM ＋ 前端
- **一句话问题**：F-27/F-28 各列表中，哪些**中文文本列**的用户期望排序是拼音序（需要增设排序键列或前端转换），哪些按默认字节序即可？
- **事实依据**（已实测，`db/probes/collation/`，线上已复测一致）：D1 默认 **BINARY ≠ 拼音序**且不报错；**无拼音排序规则**（`COLLATE PINYIN` 报错）；字典值域走 `dict_item.order_no` 可**零 schema 改动**规避——**凡是取值来自字典的列已经不受影响**，受影响的只有**自由文本列**（如机会标题、研究问题）。
- **备选项**：① 全部默认序（零改动）② 仅机会标题加拼音排序键 ③ 前端排序（数据量小可行）
- **影响面**：F-27/F-28 列表排序；若选 ② 需在 MD-06 增列或查询时转换
- **不决的后果**：列表顺序与运营直觉不一致，属体验问题、不阻塞功能

### TS-13 · 前端要不要引入轻量组件复用手段？

- **拍板人**：前端
- **一句话问题**：`frontend/` 现状是纯静态 HTML＋共享 JS，是否需要 Web Components 等组件化手段？
- **事实依据**：现状 6 页共享 `app.js`/`api.js`，已有 jsdom 回归（693 断言）；页面间重复的徽标/卡片渲染已靠公共函数收敛
- **备选项**：① 维持现状（改动最小）② 引入原生 Web Components
- **影响面**：`frontend/` 全部页面的开发方式与回归基建
- **不决的后果**：页面继续增多时复制粘贴回潮；不阻塞任何功能

### TS-15 · 前端与 API 是否长期同源？

- **拍板人**：PM
- **一句话问题**：前端与 `server/api` 是否长期同域名部署（若拆域名要补 CORS 与鉴权）？
- **事实依据**：现状设计为同源（测试也以同源断言锁死）；CI 与 runbook 均按同源部署写
- **备选项**：① 长期同源（推荐路径，零新增工作）② 拆域名（须补 CORS＋鉴权，另立设计）
- **影响面**：部署形态、`.github/workflows/ci.yml`、安全模型
- **不决的后果**：默认按同源实施；中途反悔需要返工鉴权层

### TS-16 · 长文本的截断/分段策略？

- **拍板人**：技术方
- **一句话问题**：`result_summary`（EXT-01/EXT-02）与 PD-06 注入快照接近 D1 **单行 2 MB** 上限时的处理策略是什么？
- **事实依据**：tech-stack §4 已标注「⬜ 截断策略待定」；当前查询返回经 demo 契约，实际远小于 2 MB
- **备选项**：① 应用层截断＋留痕标注（与 TS-11 应用层校验同一取向）② 分段多行 ③ 混合（摘要截断＋全文走对象存储，需新增依赖）
- **影响面**：F-09 F-12 F-24 F-25
- **不决的后果**：真实接入后大返回体可能撞 2 MB 直接报错（D1 层拒绝写入）

### TS-17 · `CFG-04` 要不要增补 `retry_delay_sec` / `dead_letter_flag`？

- **拍板人**：PM
- **一句话问题**：重试间隔与死信开关要做到「业务可配置」，还是维持代码固定？
- **事实依据**：schema §5.1 登记为待确认；现状 `CFG-04` 只有 `retry_limit`（≤100，对齐 Queues 上限），重试间隔为代码固定值；F-26 消费侧已实现兜底
- **备选项**：① 增补两列（配置化，须改 schema＋种子＋F-02 写入校验＋F-06 消费）② 维持代码固定（零改动，间隔调整走发版）
- **影响面**：F-02 F-06 F-26；选 ① 触发 schema 变更流程（Q-xx 登记）
- **不决的后果**：维持现状行为；不会坏，只是间隔不可按目标调

### TS-18 · `mock/` 是否独立于 `prototype/`？

- **拍板人**：PM
- **一句话问题**：mock server（`:8788`，本机验证用）留在 `prototype/` 内还是独立成目录/独立部署物？
- **事实依据**：现状 `prototype/mock/index.js`；tech-stack §8 原文「目录归属」
- **备选项**：① 留在 `prototype/`（现状）② 独立 `mock/` 顶层目录
- **影响面**：目录归属与 CI 路径；纯组织问题
- **不决的后果**：无功能后果；仅影响新人找文件

### TS-19 · 是否建立独立预览环境？

- **拍板人**：PM ＋ 技术方
- **一句话问题**：验收是在本地（`wrangler dev --remote` 连远程 D1）还是建独立预览环境（独立 D1 ＋ Queues）？
- **事实依据**：账号现有远程库 3 个（业务 1＋探针 2）；`wrangler dev --remote` 已实测可用（workers.dev 域名大陆不可达的运维事实见 runbook §7）；建预览环境有独立资源与配置成本
- **备选项**：① 本地 remote dev 即预览（零新增资源）② 独立预览环境（数据隔离更好，须再建一套 D1+Queues）
- **影响面**：验收流程、数据隔离、成本
- **不决的后果**：默认按 ① 执行；业务方要看数据时需另约通道

### TS-20 · `server/` 五模块打包为几个 Worker？

- **拍板人**：技术方
- **一句话问题**：采纳 tech-stack §7.3 已登记的倾向（`api`＋`task-runner` 分、`agent-orchestrator`＋`tool-executor` 合），还是别的拆法？
- **事实依据**：§7.3 已写倾向与理由（入口性质不同分；调用链紧合，省一次 Service Binding 往返）；**该决定不影响 schema 与模块职责边界**
- **备选项**：① 采纳倾向（2 个 Worker）② 单 Worker 全合 ③ 五模块全分
- **影响面**：部署配置与 Service Binding；不阻塞设计与开发
- **不决的后果**：实施时必须先定；拖着会卡部署 PR
