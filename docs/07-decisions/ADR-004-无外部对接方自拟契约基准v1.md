# ADR-004 · 无外部对接方：11 条外部契约自拟冻结为基准 v1，自造值允许进断言

> **决策记录（ADR）**——依用户裁决（2026-09-21）直接升出，无请示包前置。
> **一句话结论**：项目当前**没有外部系统对接方**，等不来的 11 条契约（T-01~T-10 + T-22）由我方以「平台方 + 对接方」**双重角色自拟答案**，冻结为**契约基准 v1**；自造值从「demo 占位（等真值）」升格为「自拟基准（已冻结）」，**允许进测试断言**（断言须标注基准版本）；「真实返回」红线的口径改述为「**来源可追溯**」。

## 1. 问题

**门禁 C 的 11 条外部契约（T-01~T-10 + T-22）原本全部等对接方提供真实事实。但项目现状是：没有外部对接方，也排不出对接排期——等到何时？**

两个必须先说清的现状事实：

**事实一：门禁 C 永远不会自己关闭。** `external-deps.md` §7 的未关 11 条的「谁提供」列全部是「对接方」或「技术方（取决于对接事实）」。没有对接方，这些条目按原口径**逻辑上不可能关闭**，业务产品也就永远停在「平台底座可用、业务产品未通」。

**事实二：demo 占位机制已经把「自造」做了一半。** §2 各表的历史深度 / 权限范围、§5 的 12 个 tool_code、§6 的七类响应结构，全部是**我方已经发明的假设值**（带 `*` 标记），mock server 已按它们跑通全链路。区别只在于：这些值**法律地位是「占位符」，不得进断言、不得当真**。也就是说，问题不是「要不要自造」（已经在造），而是「**自造值给不给正式名分**」。

## 2. 备选

| 方向 | 内容 | 后果 |
| ---- | ---- | ---- |
| ① 维持等对接方 | 11 条继续挂未决，demo 不进断言红线不动 | 业务产品无限期不可用；mock 与生产两套口径永久分裂；**被否决** |
| ② 仅造演示数据 | mock 层造数据让页面有内容，契约仍挂未决 | 页面好看但「可用」仍不能宣称；两套口径问题依旧；**被否决** |
| ③ **自拟契约基准 v1（采纳）** | 我方双重角色自拟 11 条答案，冻结为基准；自造值转正、可进断言（标注基准版本）；真对接方出现时按 ADR 修订替换 | 纪律上「自造」与「真实」的边界必须重新划清——以「来源可追溯」替代「外部真实」 |

**采纳方向 ③ 的理由**：平台的客户是京东超市运营与 PM，本系统的价值链路（找信息→找问题→拆旅程→比标杆）**先在自拟契约上跑通**，比在「空转等待」中腐化更符合 BRD 意图；且既有 demo 值本就按原型真实条件句式（EV-1027/1031/1035/1041）拟定，质量足够当基准。

## 3. 裁决

1. **11 条契约自拟冻结为基准 v1**：T-01~T-10 + T-22 由我方自答（具体内容见 `external-deps.md` v1.3 §7 各行「处置结果」），来源标注「自拟基准 v1（ADR-004）」。
2. **自造值转正**：`*` 标记的语义由「demo 占位：等对接方真值」改述为「**自拟基准 v1 值：ADR-004 冻结，可进断言**」。标记本身保留（它们标记的正是「哪些值是我方自拟的」这一可追溯事实）。
3. **允许进断言**：测试断言可引用自拟基准值，断言文案须标注基准版本（如「基准 v1」）。**既有 36 套件不强制立即改写**（其「只断结构与语义」的现状依然成立），后续补数值断言时按新口径写。
4. **红线口径改述**：PRD-M5 约束 1「真实返回」在自拟契约语境下改述为「**返回值与契约来源可追溯**」——查询返回须能追溯到「哪个契约基准的哪条约定」，**不得凭空生成**（mcp-client.js「返回值不由本层生成」的边界不变）。测试文件头「demo 数值不进断言」注释的批量 sweep 列为待办，不改不破坏任何用例行为。
5. **替换通道**：未来出现真实对接方时，不直接改值——**走 ADR 修订**（新 ADR 登记差异 + 契约基准 bump v2 + 种子与断言同步），保持「编号是主键、变更有留痕」。

## 4. 不变的部分（重要）

- **白盒原则硬红线不动**（宪法 v3 仅此一条硬红线，本裁决未触及宪法）。
- **生产零写不动**：自拟契约改变的是「查询什么、返回什么」，不改变「平台对生产库零写」。
- **D1 表结构不动**：T-06 失败语义自拟为「不扩 `QUERY_STATUS` 值域（ok/fail/running）」的两态映射，**无新 Q-xx、无 DDL 变更**。
- **证据四要素不动**：来源 / 条件 / 时点 / 适用范围的留痕要求照旧——自拟契约下它们依然必须完整。
- **TOL-12 登记不存在、TOL-03/TOL-10 能力不足**等「缺口结论」照旧成立——自拟的是契约，不是把缺口造没。
