# ADR-002 · 四条次级命名维持现名

## 1. 问题

**`schema.md` §8.3 列出的四条「次级命名」，最终用哪个词？**

这四条不是表结构问题，而是**用语口径**问题——四条**当前名都已在 §8.1 的唯一命名体系内自洽**，备选的收益只是「措辞更顺」。业务侧的问法是：这四个地方，用哪个词才不至于让读者望文生义。

判定所需的**事实底**（`DEC-PACK-001` §2.0）：

| # | 命名对象 | 当前取值 | 当前名实例数 | 分布 | 备选名 | **备选名实例数** |
| - | ---- | ---- | ---- | ---- | ---- | ---- |
| 1 | 研究建议表 | `research_proposal` | 3 | 全在 `schema.md` | `research_request` | **0** |
| 2 | 追问消息表 | `followup_message` | 4 | 全在 `schema.md` | `research_dialogue` | **0** |
| 3 | 口径检查任务类型 | `goal_check` | 2 | 全在 `schema.md` | `metric_check` | **0** |
| 4 | 字典表 | `dict_type` / `dict_item` | **18（跨 5 文件）** | `schema.md` 11 ｜ `tech-stack.md` 1 ｜ `external-deps.md` 2 ｜ `db/probes/type/README.md` 3 ｜ `db/probes/collation/schema.sql` 1 | `code_table` / `code_value` | **0** |

> **零实例项单独标出**：**四条备选名全部 0 实例**（只作为「备选」在 §8.3 被提及）。按「零实例改名成本最低」的判据，**四条改名都不会断引用链**；真正的成本差异在**当前名被谁引用**。其中第 4 条的当前名是**唯一跨文件**的一条，且波及的 `db/probes/type/README.md` 与 `db/probes/collation/schema.sql` 是**已落盘的实测证据**——回改它们会让证据偏离生成时点。

## 2. 备选

**逐条的歧义点（摘自 `DEC-PACK-001` §2.1~§2.4）：**

| # | 备选名 | 歧义点 | 若改的连带 |
| - | ---- | ---- | ---- |
| 1 | `research_request` | ① 与同表字段 `research_question` 语义邻接，易读成「把研究问题打包成的请求」；② 读起来是**系统动作**，而实际语义是 **PM 提出的建议**（BRD 全篇只用「建议」） | **必须同改** `OBJECT_TYPE` 字典值 `proposal`（否则「表叫 request、字典值叫 proposal」双词并用，直接违反术语口径） |
| 2 | `research_dialogue` | ① 会被读成「研究本身的对话化」，与 `MD-07` 的追问链**重叠**；② 改名后与 F-31「追问**对话**页」之间形成「页面叫对话、表叫 message」的反向错位 | `PD-07` 本体 + `EXT-01.message_id` + §11 索引 |
| 3 | `metric_check` | **语义收窄**——`metric`（指标）会把含义限定为「只查指标口径」，但 `CFG-05.target_field` 实际走 `dict:GOAL_FIELD` **六字段**（业务目标 / 范围 / 时段 / 约束…），非仅指标 | **必须同改** `CFG-05.target_field` 的取值集合——**二者不可只改其一**，否则名实不符 |
| 4 | `code_table` / `code_value` | 本表**列名已含 `code`**（`item_code` / `dict_type_code`），改名后形成 `code_table.code_value.item_code` 的**三级 code 堆叠**，更绕 | 5 文件 18 处；其中 2 份为已落盘证据（只能加注、不能回改） |

**统一维持的对照选项**：四条**均维持现名**——理由见 §3。

## 3. 最终

**采纳「四条全部维持现名」。**

| # | 命名对象 | **最终取值** | 备选（未采纳） |
| - | ---- | ---- | ---- |
| 1 | 研究建议表 | **`research_proposal`** | ~~`research_request`~~ |
| 2 | 追问消息表 | **`followup_message`** | ~~`research_dialogue`~~ |
| 3 | 口径检查任务类型 | **`goal_check`** | ~~`metric_check`~~ |
| 4 | 字典表 | **`dict_type`** / **`dict_item`** | ~~`code_table` / `code_value`~~ |

**裁决理由（四条共用）**：

1. **当前名都已在 §8.1 的唯一命名体系内自洽**——四条不存在「同一概念两个名」的问题，改名的收益只是措辞偏好；
2. **第 1、3 两条若改名，必须连带改字典值或字段取值**，影响面从 3 处/2 处扩大，且都属于「名与实」的连带风险；
3. **第 4 条是唯一跨文件（18 处 / 5 文件）**，且波及 2 份**已落盘的实测证据**——按本项目对证据文件的纪律（不改生成时点的证据），改名只能加注，会造成全库新旧名并存，**恰好违反本决策要维护的那条口径本身**；
4. **净收益对比**：四条备选的收益都是「措辞更顺」，成本从「改 2 处」到「改 18 处 + 污染 2 份证据」不等——**统一维持现状的净收益高于任何一条改名的收益**。

**第 3 条的特殊性（唯一置信度「低」的一条）**：

`goal_check` 与 `CFG-05` 的实际校验范围**名实相符**；而 `metric_check` 会造成**名与实不符**。但这一点**取决于一项尚未确认的事实**——

> **口径检查实际校验的是「整份六要素」还是「只有指标口径」？**

若确认为**后者**，则应改判 `metric_check`，**且必须同改** `CFG-05.target_field` 的取值集合。本 ADR 按「维持 `goal_check`」执行，但**保留该前置条件**（见 §7）。

## 4. 权衡

| 得到 | 失去 |
| ---- | ---- |
| **零改名动作**——不产生任何迁移、不触碰任何引用 | 「措辞更顺」这一层收益（主观、不可验收） |
| 四条备选名**零实例**，故**没有"断引用链"的风险被引入** | — |
| 保住了「同一概念全库唯一命名」不被自己破坏（第 1、4 条若改会破坏它） | — |
| `dict_type` 的 `dict_` 词根与全库值域写法 `dict:XXX` **同根**，辨识度一致 | — |

**一条重要的澄清**：`dict:` 是**值域标记语法**，不是表名引用——所以严格说**表名不必与标记同根**，改名不会破坏 `dict:` 语义。这一条被排除出理由，不作为「必须维持」的论据（避免把「偏好」包装成「约束」）。

| 维持 → 改第 4 条 | 改 5 文件 18 处；其中 2 份**已落盘探针证据**只能加注、不能回改 | **中**——改名本身容易，但会留下「历史名」并存 |
| **不可逆的部分** | —— | **本决策未产生不可逆代价**——四条备选名仍可随时采用（零实例，无历史包袱）。这是「维持现状」相对「改名」的另一项优势：**它把选择权完整留到了将来** |

## 7. 前置核对条件（仅第 3 条）

`DEC-PACK-001` §2.7 对第 3 条标注置信度 **低**，并附前置条件。**下列成立时，第 3 条应改判**：

- **确认「口径检查」的实际校验范围只针对指标口径** → 改判 `metric_check`，**并且必须同改** `CFG-05.target_field`（当前走 `dict:GOAL_FIELD` 六字段）的取值集合——**二者不可只改其一**。

> 其余三条（第 1 / 2 / 4 条）**无前置条件**，裁决即终局。
> 第 3 条的确认**不阻塞建表**——`TASK_TYPE` 的表结构与种子数据均可先按 `goal_check` 落，将来改判时同步改取值即可。
