## DEC-PACK 与 ADR 的区别（本目录的核心规矩）

| | 决策请示包 DEC-PACK | 决策记录 ADR |
| ---- | ---- | ---- |
| 何时写 | **裁决前**——只摆事实、列选项、给推荐 | **裁决后**——记录选了什么、为什么 |
| 谁拍板 | 里面**不拍板**；`【待我裁决】` 由 PM 填写 | PM 已拍板 |
| 是否改上游 | **不改变上游**，只读现状 | 按结论去改上游（`schema.md` / 配置等），并 bump 版本 |
| 编号 | `DEC-PACK-00N` | `ADR-00N`（`AGENTS.md` 编号体系） |
| 生命周期 | **一次性底稿**——裁决后**保留作证据**，不回改 | **长期有效**——是结论的唯一权威表述 |

> **ADR 不得写成变更日志**：每份 ADR 只承载「问题 / 备选 / 最终 / 权衡 / 影响面 / 回滚代价」六段，**不记「我改了几处」这类流水账**——改动清单的职责在上游文件的版本行与本 README 的目录表。

> **上游版本钉版不回溯**：各 ADR「上游约束」里写的「宪法 v1」「`schema.md` v1.2」是**撰写时点**的版本钉版，**不随上游改版回溯修改**——否则会伪造成「该 ADR 写于新版之下」。上游版本漂移由**上游自己的变更记录**承担（如 `AGENTS.md` v2 变更行、`schema.md` v1.3 版本行）。**判据**：若新版只做**非规范性**改动（如 v2 仅校正索引状态列，未改编号/术语口径），ADR 结论**不受影响**、无需任何动作；若新版改了 ADR 所依赖的口径，则须**新开一份 ADR** 说明，而不是回改旧 ADR。
