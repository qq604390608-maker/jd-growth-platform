# ADR-003 · 机会六要素必填，未知项用 NULL / 空串二态

> **决策记录（ADR）**——由 `DEC-PACK-001` §3.7 的裁决升出。预填值经 PM 确认为最终裁决。
> **一句话结论**：六要素**必须填**；其中「未知项」用 `NULL`（= 未评估）与空串（= 已评估且确无未知项）**两态**区分——**既不放过漏评估，也不逼人编造未知项**。

## 1. 问题

**机会的六个要素要不要在库里强制「必须填」？尤其「未知项」这一项——能不能留空？**

业务侧的问法：一个机会被记录下来时，六项都得写清楚；但「未知项」的意思是「我还查不清的东西」——**那当真的什么都查清了、没有未知项时，这一栏该写什么？**

**两个必须先说清的现状事实：**

**事实一：现状的「必填」是空的。**

- `MD-06` 的六个要素字段的「是否可空」列**全部标 `N`**（NOT NULL）；
- 但 **D1 的 `NOT NULL` 不拦空串**（实测：`''` 与 `NULL` 是可区分的两种状态，`NOT NULL` 只拦后者）——**所以六要素实际上一条都没被真正「强制非空」**，写空串照样入库。
- **结论：「必填」若要落地，必须加 `CHECK`，光靠 `NOT NULL` 没用。**（这条直接决定了本决策的落地形态。）

**事实二：`schema.md` 的措辞与表定义互相打架。**

§12 的 Q-05 原话写「当前 `unknown_item` **可为空说明**」，而表里该字段标 **`N`**。两种读法（「可以为空说明」/「可留空的说明」）**都与 `N` 冲突**。本裁决**以「该字段语义上本就允许空」为准**，把表定义向 `Y` 对齐，矛盾就此消解（`DEC-PACK-001` §5.1 记录在案）。

**事实三：原型没有给过「没有未知项」的反例。**

原型 8 条机会（OPP-014 / 013 / 012 / 011 / 010 / 009 / 006 / 005）的 `unknown` **全部有实义内容，无一条为空或空串**。即：**mock 数据里从未出现「没有未知项」的机会**——这正是「该不该允许空」无法从原型得出结论的原因。

## 2. 备选

| 选项 | 一句话 | 满足 F-28「六要素齐全」 | 满足 F-15「允许保留待查证解释」 | 反悔难度 |
| ---- | ---- | ---- | ---- | ---- |
| **A · 六个字段全强制非空** | 六字段全部 `NOT NULL` + `CHECK` 拒空串 | ✅ **字面满足** | ❌ **不满足**——「确无未知项」的机会只能**编造**一条假未知项 | **中**（见下） |
| **B · `unknown_item` 允许为空** | 五字段加 `CHECK`；`unknown_item` 允许空 | ⚠️ **取决于「齐全」的解释**（「六项都有值」→不满足；「六项都被评估过」→满足） | ✅ **满足** | 低 |
| **C · `NULL` / 空串二态** | `NULL` = 未评估；`''` = 已评估且确无；五要素加 `CHECK` | ✅ **满足**（六项都有**评估状态**，无漏评估） | ✅ **满足**（「确无未知项」是合法取值，不必编造） | **低—中**（结构不变，退化为 B 只需改约定） |

**课程口径对照（`DEC-PACK-001` §3.4）**——这是本决策的关键分析：

| 课程口径（PM 转述） | 最接近的库内落点 | 原文 |
| ---- | ---- | ---- |
| 允许保留待查证解释 | `BRD.md` **F-15 基础查证** 验收要点 | 「对现象的解释**必须标明尚未验证的部分**；支持『值得进一步研究』」 |
| 六要素要说清楚 | `BRD.md` **F-28 机会列表与详情页** 验收要点 | 「**六要素齐全**；证据可回查到查询记录」 |

> **来源诚实声明**：这两句课程口径**本库内查无原文**（全库检索 `待查证` / `说清楚` 均无）。它们是 PM 转述的要求，此处按转述处理，不当作 BRD 原文引用。

**是否冲突——表面冲突，实质不冲突**：

- 两条约束**对象不同**：**F-15 约束「解释的完整性」**（允许不全，但**必须标明哪里不全**）；**F-28 约束「六要素的记录完整性」**（六项都要有落点）。二者作用在**不同层**，本身可共存。
- **冲突只在一种实现下发生**：把「未知项」强制成「**必须有实义未知**」——那就把 F-15 的「允许不全」改写成了「**必须编造不全**」。

**结论**：**写法 C（选项 C）是唯一同时满足两条口径的写法**；写法 A 与 B 各牺牲一条。

## 3. 最终

**采纳选项 C —— `NULL` / 空串二态。四件落地动作：**

| # | 动作 | 落点（`schema.md` v1.2 已执行） |
| - | ---- | ---- |
| 1 | **`unknown_item` 由 `N` 改 `Y`**，同时消解与 §12 措辞的矛盾 | MD-06 表 |
| 2 | **其余六个要素字段保持 `N` 并加 `CHECK (length(trim(x)) > 0)`**——拒**空串** | MD-06 表 |
| 3 | **「六要素齐全」的判定口径**：＝**六项都被评估过**（各自有评估状态），**不等于**六项都必须有实义内容。判定式：`unknown_item IS NULL` → **不齐**（触发待补）；`unknown_item = ''` → **已评估且确无未知项**，**计入齐全** | MD-06 表尾注 + §10 加注 |
| 4 | **应用层约定**（谁写 `NULL`、谁写 `''`）写入 CFG-05 或将来 M3 的 `agent.md` | ⏳ 待 `agent-runtime/`（本 ADR §7 说明） |

> **「六个要素字段」的准确清单**（避免歧义）：**「对应目标」占两列**（`goal_id` + `goal_version_no`），其余四项为 `target_object` / `phenomenon` / `initial_basis_note` / `research_reason`——**共六个字段**受必填约束；`unknown_item` 单独按二态处理；`opportunity_title` **不在六要素内**，不在本次范围。

### 3.1 一处必须在案的技术细节（实测修正了原表述）

`DEC-PACK-001` §3.7 的原表述是「其余五要素字段加 `CHECK`：**拒 `NULL` 与空串**（表达式即 `CHECK (length(trim(x)) > 0)`）」。

**实测表明这两句不能只取其一**：

> `length(NULL) > 0` 求值为 **`NULL`**（不是 `FALSE`）→ **`CHECK` 会放行 `NULL`**。

即：**`CHECK (length(trim(x)) > 0)` 这个表达式本身拦不住 `NULL`**。它之所以有效，是因为字段**同时保留了 `NOT NULL`**。所以本决策的实际落地形态是**两件套**：

| 约束 | 拦什么 | 实测依据 |
| ---- | ---- | ---- |
| `NOT NULL` | **只拦 `NULL`**（不拦空串） | `db/probes/type/README.md` §2.2、§3 落差表第 8 行 |
| `CHECK (length(trim(x)) > 0)` | **只拦空串**（放行 `NULL`） | 同上 §2.6、§3 落差表第 19 行 |

**二者不可互相替代** —— 这条已写入 `schema.md` MD-06 表尾注与 `tech-stack.md` §3.3，避免将来有人以为「加了 CHECK 就万事大吉」。**这也正是为什么本次实测是这项决策的前置条件**：如果没有 `NULL` / 空串可区分这一实测结论，写法 C 根本无法成立。

### 3.2 未加的一处约束（如实登记）

`unknown_item` 本次**只改可空性，未加库级 CHECK**——因为 `DEC-PACK-001` §3.7 的落地动作第 2 条只要求「其余**五**要素字段」加 CHECK。

> **可选式（若将来希望库级守住二态）**：`CHECK (unknown_item IS NULL OR unknown_item = '' OR length(trim(unknown_item)) > 0)` —— 该式允许 `NULL` 与 `''`，拒绝纯空白串（如 `'   '`），语义上完整覆盖二态。**是否追加属新决策，本 ADR 不代做。**

## 4. 权衡

| 得到 | 失去 / 代价 |
| ---- | ---- |
| **同时满足 F-15 与 F-28**，不牺牲任何一条 | 需要**应用层明确约定**「谁写 `NULL`、谁写 `''`」——**约定一旦混用，本方案退化为选项 A** |
| **不必编造未知项**——消除「为过约束编数据」的污染源 | 多一个「两个空状态」的语义负担，前端与写入侧都要遵守 |
| **反悔成本最低**：结构不变，退化为 B（改约定）或加强到 A（改 CHECK）都容易 | 判定「齐全」多一个维度（要看 `unknown_item IS NULL`，不能只看非空） |
| **与原型不冲突**：原型的 8 条「有未知项」正对应二态中的一态；本决策只是**补上原型没给出的另两态**（未评估 / 确无） | — |
| **技术前提已被实测证实**（`NULL` 与 `''` 可区分） | **风险**：该实测为 `--local`（miniflare）结论，**线上 D1 未验证** |

**与选项 A 的关键差异（这是本决策的核心价值）**：

选项 A 会**逼出编造的未知项**——而这类假数据一旦入库，**事后无法自动区分「真未知」与「为过约束编的未知」**。这是**不可逆的数据污染**；相形之下，本方案的「约定混用」风险是**可检测、可修复**的。

| 想要改成 | 需要做什么 | 代价 |
| ---- | ---- | ---- |
| C → **B**（放宽） | 改应用层约定；`CHECK` 可保留（六字段仍非空） | **低**——结构不变 |

| **不可逆的部分** | —— | **本决策本身不产生不可逆代价**——**这恰是选 C 而非 A 的核心理由**：C 的反悔只需改约定；而 **A 一旦运行，编造的未知项会永久混入数据，无法事后区分真假** |
