## 1. 业务背景

京东超市运营与产品经理挖掘用户增长机会时，依赖一套前置调研流程：找信息 → 找问题 → 拆旅程 → 比标杆 → 定关键行为。当前该流程缺乏系统化沉淀，信息分散、证据不可回查、两阶段研究缺乏衔接，导致机会挖掘质量依赖个人经验、重复调研频发。

本平台将上述流程沉淀为系统化能力，形成「建议型系统」：**半 AI、半流程、半系统化**。AI 负责研究发现与判断建议，程序负责确定性的调度、存储与执行，产品经理保留关键人工节点。

## 2. 项目目标与定位

### 2.1 目标

1. 把「目标 → 发现 → 人工节点 → HVA 研究 → 结果 → 追问」全链路系统化，过程留痕、证据可回溯。
2. 让机会发现与 HVA 分析两个研究阶段共享上下文、人工衔接，避免重复研究。
3. 所有外部系统查询经 MCP 工具执行，真实返回、失败留痕，杜绝"用模型预期替代查询结果"。

### 2.2 系统形态

- 建议型系统：平台产出机会与研究成果供人决策，不自动立项、不自动执行业务动作。
- 前后端分离：运营端工作台为前端，服务端提供接口，动态数据均来自数据库。

## 4. 功能点清单

> 每条含「功能描述 / 输入→输出 / 验收要点」，可直接作为后续子 PRD 的开发依据。

### M1 平台任务程序（组织者 / 调度层）

职责：目标与研究任务管理、组织上下文、加载指令与能力说明、启动任务、保存产出、提供结果。所有不需要 AI 决策的确定性工作均由程序执行。

#### F-01 研究目标登记与口径管理

- **功能描述**：登记业务方提供的目标六要素：业务目标、指标口径、业务范围、关注时段、已知约束、提供方与材料。口径不清时列出缺少的信息由业务方补充；**Agent 和产品经理不能替业务方另定指标定义**。目标更新后保存变化；已有研究保留启动时采用的目标和范围，新目标建新研究版本，不混两个时期的判断。
- **输入 → 输出**：目标材料 → 结构化研究目标（版本化）。
- **验收要点**：同一研究不因目标中途更新而被悄悄替换；待补项清晰列给业务方。

#### F-02 机会发现任务调度

- **功能描述**：到达运行条件（运行频率 / 时长 / 调用限制按业务需要配置）时创建发现任务，准备一阶段上下文（目标、范围、背景、相关历史、能力说明），调用机会发现 Agent。
- **输入 → 输出**：业务关注配置 → 发现任务＋Agent 启动。
- **验收要点**：任务程序决定何时启动；Agent 只在任务内选择分析方法。

#### F-03 研究建议管理（人工节点）

- **功能描述**：产品经理选机会＋提研究问题（必需），可补候选行为假设、人群限制（可选）。平台检查并保存；问题不明确只补充要查清的内容，不要求重填已有材料。同一份研究建议重复提交不重复启动相同任务。
- **输入 → 输出**：选定机会＋研究建议 → 保存的建议记录。
- **验收要点**：建议与机会版本关联；重复提交幂等。

#### F-04 HVA 研究任务调度

- **功能描述**：研究建议提交后，组织二阶段上下文（所选机会及版本、产品问题、可选假设、关联目标与证据、相关历史研究），调用 HVA 分析 Agent。
- **输入 → 输出**：建议记录 → HVA 任务＋Agent 启动。
- **验收要点**：第二阶段启动时点＝建议提交；已允许的查询工具按任务规则执行。

#### F-05 追问与版本管理

- **功能描述**：产品经理在已有研究上提新问题 → 关联原研究建立新任务；问题或范围修改后形成新版本，已有任务继续使用启动时的版本。
- **输入 → 输出**：新问题＋原研究 → 新研究任务（关联）。
- **验收要点**：原研究结果与依据继续保留；新旧版本不混。

#### F-06 任务记录与异常恢复

- **功能描述**：每次任务保存：启动依据、指令与能力版本、查询及返回记录、已形成内容、当前状态。失败按配置限制重试（代码驱动的重跑机制），持续失败暂停受影响研究；真卡死就保留已完成部分停止。**运行失败本身不能作为否定某项 HVA 的研究依据**。研究内容与运行状态分别记录；任务受阻后定位缺口、保留已完成的工作。
- **输入 → 输出**：任务执行过程 → 任务记录＋状态机流转。
- **验收要点**：状态机；停止状态不自动重启；研究内容与运行状态分别记录。

##### 任务受阻处理矩阵（F-06）

任务受阻时，系统按以下矩阵处理，核心原则：**研究内容与运行状态分别记录；定位缺口、保留已完成的工作**。

| 情况 | 系统处理 | 继续研究的条件 |
| ---- | ---- | ---- |
| 目标或指标口径不清 | 向业务方列出需要明确的内容，保留已有目标信息 | 业务方补充必要口径 |
| 接口未返回研究所需信息 | 记录缺失内容及其对当前问题的影响，保留已完成部分 | 接口可取得所需信息后，检查是否适用 |
| 来源未接入或权限不足 | 记录接口不可用原因与受影响的研究内容 | 接入或权限问题解决 |
| 查询或服务调用失败 | 保留失败原因，按配置限制重试；持续失败暂停受影响研究 | 服务恢复且满足任务继续条件 |
| 达到运行限制或人工取消 | 停止后续调用，记录未完成原因和已有工作 | 后续处理需明确是否继续；**停止状态不自动重启** |
| 研究完成但没有足够依据 | 保存已检查的范围、研究发现及判断限制 | 结果可直接查阅；新问题或新依据可用于后续研究 |

##### 状态流（F-06）

```
任务执行中 →（等待必要信息 / 处理调用失败 / 已完成 / 已停止）
处理调用失败 →（重试成功回执行中 / 等待接口恢复 / 检查继续条件）
检查继续条件满足 → 恢复原任务
```

研究问题改变时建新版本任务，已有任务沿用启动时版本。

### M2 共享上下文（信息存储）

职责：保存并组织与研究有关的信息——两阶段共同使用的背景＋研究过程中逐步增加的机会、问题和证据。存的是**内容或来源引用**，按任务挑选相关部分注入。

#### F-07 业务背景管理

- **功能描述**：目标与口径、业务知识与约束；触点清单（首页推荐位、搜索结果页、京东超市频道等）。
- **输入 → 输出**：业务方材料＋预置触点 → 背景库。
- **验收要点**：Agent 查询前可获知"能查哪些、该往哪个方向查"。

#### F-08 可用来源与工具登记

- **功能描述**：登记五类外部系统与工具用途。**系统名称确定了信息归属，实际可查内容需通过接入能力确认**：线上流量信息 ≠ 完整用户行为序列，活动信息 ≠ 活动效果；未接入或无法查询的信息成为研究缺口，不能用系统名称代替实际证据。
- **输入 → 输出**：接入能力 → 来源与工具说明。
- **验收要点**：Agent 能知道缺少什么信息，但实际查询仍需对应接入。

#### F-09 证据管理

- **功能描述**：每项证据关联来源、查询条件、信息时点、适用范围和缺失说明——无论哪个 Agent 引用，都应能回查证据是怎样取得的。**新证据加入不覆盖原有依据**：初查后业务条件变化可重新查询，原观察仍保留当时依据。
- **输入 → 输出**：查询返回 → 结构化证据记录。
- **验收要点**：证据链完整可回溯；新旧依据并存且关联。

#### F-10 机会记录管理

- **功能描述**：机会六要素：对应目标 / 涉及对象（人群、品类或旅程环节）/ 观察现象 / 初步依据（资料或查询的来源与时点）/ 研究理由 / 未知项。同一问题出现新证据 → 关联到已有机会；新现象有独立价值 → 新机会记录；**暂不研究的机会仍保留记录**，条件变化或新证据后可再选，不必从零整理。
- **输入 → 输出**：机会发现产出 → 机会记录（含状态）。
- **验收要点**：机会的选择取决于证据、相关性与问题是否值得追问，而非文案是否肯定。

#### F-11 研究结果与历史管理

- **功能描述**：保存研究结果、历史研究；后续业务工作形成验证结果时，平台可关联其结论与来源供以后研究查阅（外部验证的执行与效果计算由业务工作完成）。
- **输入 → 输出**：研究结果＋外部验证 → 历史研究库。
- **验收要点**：后续研究可引用历史，避免重复研究。

#### F-12 上下文按任务组织注入

- **功能描述**：两个维度：**类型**（需要什么类型的信息）+**范围**（只查和京东超市有关的触点 / 只看业务方负责的品类），以类型为主、范围是具体约束。一阶段给：目标、背景、可用来源、已有机会摘要；二阶段增加：所选机会、产品问题、已有证据、相关历史研究。
- **输入 → 输出**：任务描述 → 该任务的工作空间初始化。
- **验收要点**：初始化是确定性程序行为，不是每回随机；只传递一句"继续分析"无效，要求 PM 重新粘贴全部资料也不应发生。

### M3 机会发现 Agent（第一阶段）

职责：围绕业务目标寻找潜在机会与问题——找线索、查证现象、整理值得关注的问题，止于"机会＋初步依据"，供人选择。**是否存在值得关注的候选 HVA，要等 PM 提出研究问题后由第二阶段分析。**

#### F-13 角色指令配置

- **功能描述**：agent.md 定义"你是谁"：本阶段职责、输入、输出与结束条件；与 Skill（能消费什么）、程序（能干什么）一起构成领域能力。
- **输入 → 输出**：— → agent.md。
- **验收要点**：结束条件二选一：形成机会与初步依据 / 说明本轮未发现足够依据。

#### F-14 围绕目标寻找线索

- **功能描述**：接收目标、背景、可用来源、历史研究，围绕目标决定先查看哪些信息。线索来源：经营表现变化、人群已有行为差异、用户反馈、新的业务信息——不同来源提供不同观察角度。线索必须关联到具体人群或用户旅程：**记录"谁在什么环节遇到了什么现象"，而非仅罗列一组变化**。
- **输入 → 输出**：目标＋背景 → 关联人群 / 旅程的线索。
- **验收要点**：线索对人群差异的使用停留在发现现象与基础查证，不提前下 HVA 判断。

#### F-15 基础查证

- **功能描述**：Agent 选择需要核对的信息 → 程序实际执行查询或必要的基础统计 → 结果及来源返回。五项检查：来源（哪份资料哪次查询）/ 适用范围（人群、渠道、旅程环节是否对应当前目标）/ 信息时点（业务条件是否已变化）/ 已有机会（是否记录过相同问题）/ 信息缺口（还缺什么、缺失影响哪项判断）。
- **输入 → 输出**：线索 → 查证后的初步依据。
- **验收要点**：对现象的解释必须标明尚未验证的部分；支持"值得进一步研究"，不给完整人群对照和 HVA 结论。

#### F-16 机会形成与去重

- **功能描述**：依据足够 → 保存机会与初步证据；相同问题关联更新；依据不足 → 保存检查范围与信息缺口，允许本轮不产生新机会。
- **输入 → 输出**：查证结果 → 机会记录或缺口记录。
- **验收要点**：没有足够依据也是合法产出（对应领域问题的优化方向）。

#### F-17 两步衔接

- **功能描述**：机会＋初步依据作为产品经理输入的前提；拿到结果之后的对话过程作为第二个 Agent 的输入；必要信息可能需要 Agent **反过来问产品经理**。
- **输入 → 输出**：机会记录 → PM 决策上下文。
- **验收要点**：衔接经人工节点，不自动交接（见 M1-F-03/04）。

### M4 HVA 分析 Agent（第二阶段）

职责：围绕产品研究问题深入分析——人群比较、候选行为寻找与检验、其他解释查证、结果整理。HVA＝可能与用户长期价值有关、值得进一步研究的关键行为；研究完成前都属于候选行为。

#### F-18 角色指令配置

- **功能描述**：agent.md 定义第二阶段职责、输入、输出与结束条件。
- **输入 → 输出**：— → agent.md。
- **验收要点**：结束条件：形成有依据的研究回答 / 说明无法完成判断的原因。

#### F-19 研究起点处理

- **功能描述**：先判断问题是否适合开展 HVA 研究。三种起点：① PM 提供候选行为假设 → 检查假设对应的人群、行为与结果（**产品假设不预先作为研究结论**）；② 只有研究问题 → 根据问题与可获得的行为信息寻找候选行为再比较查证（**允许找不到有足够依据的候选行为**）；③ 问题不适合或缺少关键行为依据 → 说明问题、已有发现与 HVA 判断限制（如问题主要涉及服务体验，只说明障碍及改善方向，不硬归结为关键行为）。
- **输入 → 输出**：产品研究问题 → 研究路径选择。
- **验收要点**：三种起点的分支与保留判断。

#### F-20 人群比较与行为关系检验

- **功能描述**：候选行为五查：① 人群是否有可比基础（原有特征与表现差别未解释时，限制行为作用判断）；② 行为与结果的先后关系（行为须发生在所讨论的后续表现之前，不能把已发生的结果当行为影响）；③ 结果是否对应业务目标（口径一致）；④ 是否存在其他解释（商品、活动、权益等业务条件）；⑤ 信息是否足以支持判断（缺关键依据时说明缺口，不给确定判断）。比较条件（涉及哪些用户、观察哪个阶段、什么结果口径）随分析保存。
- **输入 → 输出**：候选行为＋人群 → 比较结果＋限制说明。
- **验收要点**：观察到行为与较好表现同时出现 ≠ 因果；某活动存在只证明有活动信息，用户是否参与、受何影响需对应记录。

#### F-21 研究结果生成

- **功能描述**：七要素组装：业务目标与研究问题 / 研究范围与方法 / 证据与关键发现 / 人群差异 / 候选 HVA 及支持情况 / 其他解释与限制 / 改善方向。每项关键发现关联实际取得的证据；**未找到足够依据支持候选 HVA 也可形成完整结果**；改善方向与发现逐项对应（针对什么人群、什么问题、为什么值得改善），活动配置、权益组合、预算与排期不在其内。
- **输入 → 输出**：比较结果 → 完整研究报告。
- **验收要点**：读者能分清"已查明的内容"与"仍存在的限制"；查询失败导致的未完成不能当否定依据。

#### F-22 继续追问承接

- **功能描述**：PM 需要继续查证时在已有研究上提新问题；Agent 检查已有依据是否仍适用（时间范围、查询条件变化时补查），再决定沿用或补查。
- **输入 → 输出**：新问题＋原研究 → 新一轮结果。
- **验收要点**：追问形成新任务但保留原结果与依据（见 F-05）。

#### 补充说明：HVA 观察两件事

1. 同样一件事不同人群有没有行为差异；
2. 发生了特定行为之后，后续表现有没有对应变化。

### M5 工具执行程序

职责：检查权限与调用条件、查询来源或执行分析、返回真实结果、保存查询依据。所有外部接口均已 MCP 化，tools 注册到 Agent，执行是纯程序。

#### F-23 工具注册与权限检查

- **功能描述**：五类系统的 MCP 工具注册到 Agent；每次请求先检查当前任务权限与调用条件（自循环步骤）。
- **输入 → 输出**：Agent 请求 → 权限判定。
- **验收要点**：权限分支互斥：允许 / 不允许，不允许时保存原因并返回受限原因。

#### F-24 查询执行与真实返回

- **功能描述**：访问 CDP（用户标签）/ 黄金眼（线上流量）/ 商品中台（超市商品）/ 营销中台（权益）/ 活动报名系统（活动），返回实际结果及限制；失败返回具体原因。
- **输入 → 输出**：查询条件 → 实际结果或失败信息。
- **验收要点**：**不能用模型预期的内容代替查询结果**；返回内容保留查询条件、来源、时点、限制。

#### F-25 查询记录保存

- **功能描述**：每次执行把条件、来源、时点、结果或失败原因写入任务记录，同时供共享上下文作为证据。
- **输入 → 输出**：执行过程 → 查询记录。
- **验收要点**：失败也留痕；记录可回查。

#### F-26 失败重试与受限返回

- **功能描述**：调用失败按配置限制重试（代码驱动的重启机制：失败记录 → 重新调起接口，把任务完整执行）；持续失败暂停受影响研究并保留已完成部分。
- **输入 → 输出**：失败事件 → 重试 / 暂停 / 受限返回。
- **验收要点**：重试是代码逻辑不是 AI 决策；实在卡死保留状态停止。

#### 补充说明：一次指标查询的完整闭环

Agent 识别要调度工具（可能经 Skill 识别）→ 工具执行（检查权限 → 调 CDP → 返回结果）→ 对结果进行分析 → 分析完记录任务。

### M6 运营端工作台（前端）

职责：前后端分离，服务端所有动态数据经接口请求，数据从数据库来。以下页面供原型阶段（十二步第③步）直接使用。

#### F-27 目标配置页

- **功能描述**：业务方登记 / 关联目标六要素；口径待补项以任务形式提示；目标更新形成新版本并提示影响范围。
- **验收要点**：不替业务方定指标；版本变化可见。

#### F-28 机会列表与详情页

- **功能描述**：按目标浏览机会（状态：候选 / 暂不研究 / 已提交研究）；详情页呈现机会六要素＋证据链（来源、条件、时点可点开回查）＋未知项。
- **验收要点**：六要素齐全；证据可回查到查询记录。

#### F-29 研究建议提交页

- **功能描述**：PM 选机会 → 填研究问题（必需）→ 可选补候选行为假设、人群限制；问题不明确时只补问题不重填材料。
- **验收要点**：提交后触发 F-04；重复提交幂等。

#### F-30 研究结果页

- **功能描述**：呈现结果七要素；每项关键发现挂证据来源与适用范围；候选 HVA 的支持 / 不支持情况并列展示。
- **验收要点**：已查明与仍受限的内容视觉可分。

#### F-31 追问对话页

- **功能描述**：基于通用 Agent 的场景化追问：拿到对应上下文信息，用对话方式再调度、查没发现的地方、注入新信息再跑。
- **验收要点**：追问建新任务并关联原研究（F-05）。

#### F-32 任务与状态页

- **功能描述**：任务运行状态、受阻原因（等待必要信息 / 等待接口恢复 / 已停止）、已完成部分；机会未被选中、任务未完成、研究未支持候选行为三类事实分别可见。
- **验收要点**：状态机口径与 4.6 一致。

## 5. 范围边界

### 5.1 in scope（功能点范围内）

F-01 ~ F-32 覆盖"目标 → 发现 → 人工节点 → HVA 研究 → 结果 → 追问"全链路＋五系统查询留痕。

### 5.2 out of scope（逐条列明，防 Agent 自作主张扩展、需求方无限追加）

- 活动玩法与权益配置
- 收益测算与立项评审（用研究结果另行开展）
- 评论区 / 客诉反馈分析（迭代方向）
- 生产环境任何写操作
- 京东全局算法因子
- 自动交接与自动立项

### 5.3 硬红线

**不写 / 不调面向生产环境会改线上数据的接口。**

## 6. 全局术语口径

| 术语 | 口径 |
| ---- | ---- |
| 候选行为 | HVA 在研究完成前一律称"候选行为"，不提前定性 |
| 共享上下文 | 本平台的信息存储机制，存内容或来源引用，按任务注入 |
| 证据 | 关联来源、查询条件、信息时点、适用范围的结构化记录 |
| 人工节点 | 机会发现与 HVA 分析之间由 PM 选机会、提研究问题，不自动交接 |
| 建议型系统 | 平台产出建议供人决策，不自动执行业务动作 |

## 7. 验收总则

1. 以功能点为单位逐点开发、逐点验收（白盒原则）。
2. 每份产物建立双向引用，拒绝孤儿文件。
3. 查询证据必须带来源、条件、时点、适用范围。
4. 运行失败不作为否定研究的依据；查询失败导致的未完成不能当否定结论。
5. 生产环境零写操作。
